## 可提交正文

主题：询问 ChatGPT / Codex 桌面应用受支持的会话导航扩展与测试接口

您好，我正在开发长对话导航扩展，希望在同一桌面应用的 Chat 与 Codex 界面中实现以下能力：

1. 在 Chat 中增加与 Codex 原生条形码式提问目录条一致的导航；Codex 保留并联动原生目录条。
2. 切换会话、刷新及重启后，按消息内容锚点恢复阅读位置。
3. 阅读历史时，在流式生成、图片加载、代码块高度变化及历史插入过程中保持位置稳定。
4. 本地字符串搜索当前显示分支的全部提问与回答，包括尚未渲染的历史，并直接定位回答中的具体匹配范围。

Computer Use 文档明确不能自动化 ChatGPT 自身，因此我们未绕过工具限制，也未对宿主执行注入或应用修改。目前只有独立预览与核心逻辑回归，不能作为真实宿主验收。

请确认是否存在受支持的桌面 UI 扩展或开发测试接口，能够：

- 获取稳定的会话、分支、轮次和消息 ID。
- 分页读取完整当前分支历史，并获得可靠的完整性状态及增量更新。
- 加载尚未渲染的历史目标，再定位消息或消息中的文本范围。
- 捕获和恢复内容锚点，订阅布局变化，明确原生和扩展谁负责滚动补偿。
- 联动 Codex 原生目录条，或在 Chat 中挂载相应组件。
- 在停用时清理 UI、事件监听和观察器，恢复原生行为。

如支持，请提供接口文档、接入权限、兼容版本、推荐测试环境及停用方式；如不支持，也请明确说明哪些能力当前不对第三方开放，是否存在官方反馈或开发者试点渠道。

环境：macOS，安装包元数据显示版本 26.924.22138、build 11645，Bundle ID com.openai.codex。
公开项目：https://github.com/AForAaron/codex-thread-navigator

感谢。

## 回复后的决策规则

- 只有通用插件安装说明、iframe UI 或截图权限：仍不足以通过 G0。
- 只有消息/历史数据接口：可实现索引部分，但不能宣称宿主滚动和目录条接入。
- 提供完整宿主扩展文档与允许的测试入口：再验证单会话识别→加载→定位→dispose 闭环。
- 明确不支持：记录原文与日期，真实接入维持未完成；不自动改成网页产品或安装第三方注入工具。
