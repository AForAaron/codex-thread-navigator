# Codex 模型来源控制页使用指南

核验日期：2026-10-02。目标是用适合现有 Codex 灰阶界面的本机控制页，配置已有 OpenCode Go Keychain，并只提供已通过 Codex 基础工具调用验证的 Go 模型。

## 当前状态与交付范围

本机控制页地址为 `http://127.0.0.1:8766/`，可在 Codex 内置浏览器展示。它读取和保存 `~/.codex/config.toml`；页面上“已保存配置”表示配置文件状态，不能据此断言正在运行的桌面聊天已切换来源。

Go provider 已注册。验收切换循环结束后，已恢复原生 OpenAI 的 `gpt-6.1-sol`、`low` 配置；相对原配置，仅新增 Go provider 定义。现有导航和额度插件保留。初始交付范围为本机控制页；随后新增的可逆会话侧栏入口见文末「左侧栏入口」。

| Go 模型 | 本次结果 | 控制页可选 |
|---|---|---|
| GPT 5.6 Luna (`gpt-5.6-luna`) | 通过隔离环境的 shell 文件读取和工具结果返回 | 是 |

验证使用随应用提供的 Codex 0.159.2。两个通过模型的结论限于本次基础任务；复杂 MCP、桌面工具、长任务及后续模型服务变化仍需实际验证。

## 打开、切换与恢复

在 Finder 双击 `<仓库根目录>/scripts/open-provider-switcher.command`，或在终端运行：

```bash
bash <仓库根目录>/scripts/open-provider-switcher.command
```

启动脚本会开启本机服务并在默认浏览器打开页面；如服务已运行，会复用它。在 Codex 内置浏览器打开同一地址即可使用。

1. 选择 **OpenCode Go**，再选 **GPT 5.6 Luna** 或 **GPT 6 Luna**。
2. 点击 **保存 Go 模型设置**，等待保存成功提示。
3. 当前任务结束后，完全退出并重新打开 Codex，再新建聊天。

保存不会替正在执行的任务更换模型。桌面重启后的实际路由尚未完成验收；首次重启后应通过新聊天核对模型来源及基础工具运行。

恢复时，在同一页面选择 **Codex / OpenAI**，点击 **恢复原生 Codex 设置**，随后在任务结束时退出、重开并新建聊天。OpenAI 的模型和推理强度继续通过 Codex 原生菜单选择。恢复使用进入 Go 前记录的原生配置字段；发现外部改动时会停止覆盖并显示错误。

若提示配置被其他程序修改，先保留外部改动，重新打开页面取得最新配置，再重新选择。修改选择后，页面的“刷新”优先刷新用量；重新打开页面更适合处理配置冲突。

## CLI 使用

已保留两个独立配置片段：

- `~/.codex/go-gpt-5-6-luna.config.toml`
- `~/.codex/go-gpt-6-luna.config.toml`

它们包含模型与 provider 两项配置。本机 CLI 0.145.0 的 `--help` 已核实，`--profile` 会叠加 `$CODEX_HOME/<name>.config.toml`；桌面随附 CLI 0.159.2 同样支持。要求本机 `codex` 命令可用且 Go provider 已注册：

```bash
codex --profile go-gpt-5-6-luna
codex --profile go-gpt-6-luna
```

这些命令选择当前 CLI 进程的模型；控制页负责持久保存桌面应用下次读取的配置。

## 用量、钥匙串与配置保护

页面从 Go 的真实 API 读取 5 小时、本周、本月**已用百分比**，重置和更新时间采用北京时间。服务有 60 秒缓存，页面每 60 秒更新；连续点击刷新可能仍返回缓存。接口不可用时显示错误或暂无可靠数据，不填造额度。

已有 Keychain 条目的 service 是 `apikey/opencode-go`，account 是当前 macOS 用户名（`$USER`）。无需在页面粘贴密钥。Codex provider 通过 `/usr/bin/security` 身份验证命令读取密钥；本机服务查询 Go 用量时也读取密钥并仅在服务内存中使用。密钥不进入前端响应或本指南。如 macOS 询问钥匙串访问授权，请核对请求来源；读取失败会在页面显示错误。

服务仅监听 `127.0.0.1`。它使用 HttpOnly、SameSite Strict 会话 Cookie，检查 Host / Origin，并在保存时核对配置 revision。配置备份与恢复记录保存在 `~/.codex/provider-switcher/` 私有目录。保存只管理模型来源相关的六个顶层字段，并保留其他配置内容。

## 停止与移除

由启动脚本新开的服务可在其终端按 `Ctrl+C` 停止，或关闭该终端。若脚本只复用了已有服务，应在原服务终端停止。关闭浏览器页面本身不会停止服务；停止服务也不会撤销已保存的模型配置。

移除前先在页面恢复原生 OpenAI，确认恢复成功。之后可停止服务，移除本项目的 `tools/provider-switcher/`、启动脚本，以及上述两个 Go 配置片段。若要清理全局配置，仅移除 `config.toml` 中本工具新增的 `[model_providers.opencode-go]` 及其 auth 子表，保留其余内容。备份目录可在确认无需恢复后单独清理。

现有 Keychain 条目、其他 Codex 配置以及导航和额度插件均有独立用途；移除此控制页不需要删除它们。避免用旧整份备份覆盖当前配置，以免丢失交付后新增的设置。

## 左侧栏入口（2026-10-02）

现有 Codex Navigator 会话现在会同时启动 `scripts/provider-rail-session.mjs`：在已有 5h 用量上方显示 44×44 的模型来源按钮，向右展开 336px 面板。Esc、关闭按钮或点击外部关闭面板；空间不足时隐藏入口，避免覆盖原生导航。

面板复用控制页的来源、模型、用量和保存流程，但通过固定操作的进程桥接（status、usage、apply）访问后端，不放宽网页接口的来源与 Cookie 校验，也不传送 API 密钥。保存后仍须任务结束时重启 Codex 并新建聊天。

继续从 Codex Navigator 启动即可加载入口。普通方式启动 Codex 不加载实验侧栏。当前会话可以单独连接：设置已有的 EXPLODEX_DEBUG_PORT 后，在本项目目录运行 `node scripts/provider-rail-session.mjs`。在终端按 Ctrl+C 正常停止该进程会移除按钮和面板；应用文件不变，已保存的模型配置仍保留。该入口复用本机 Python 后端，默认使用 `~/.pyenv/versions/3.10.12/bin/python3`；需要指定已有 Python 时可设置 `CODEX_PROVIDER_PYTHON`。

验证范围：13 项配置、HTTP 与慢用量桥接回归通过；当前侧栏会话的接入脚本执行成功。电脑操作工具禁止操作本次任务所在 Codex App，因此真实侧栏点击、视觉位置与面板保存的主机验收仍需用户确认，不能以独立网页测试代替。

## C1：Go 专用模型目录（2026-10-02 已实现）

侧栏保存 Go 设置时，会从本机 `models_cache.json` 提取已通过工具验证的模型条目，生成内容摘要命名的私有 JSON 目录，并用桌面捆绑的 Codex app-server 在临时 CODEX_HOME 中调用 model/list 校验。返回名单必须与已验证名单完全一致，然后才写入 `model_catalog_json` 和来源、模型设置。

缓存会随登录状态和服务刷新，不能保证持续包含两个 Luna。缓存缺失或条目不足时，允许使用之前已通过后端校验的目录：文件名、完整摘要与模型集合都要一致，并重新进行后端校验。目录被修改或没有可靠回退时，不切换配置。条目元数据来源是缓存快照；目录校验不证明 Go 支持全部上下文、推理或桌面工具能力。

恢复 OpenAI 时精确恢复原来的 model_catalog_json（原来不存在才删除字段），并保留其他程序对非受管理字段的修改。保存中断时，启动读取会对照 pending 的前后配置摘要：已经提交则完成记录，尚未提交则恢复原状态记录；配置同时被外部修改时停止自动处理。

本轮检查：18 项回归通过；真实目录通过捆绑后端校验；GPT-6 Luna → GPT-5.6 Luna → OpenAI 的真实配置往返成功，原生配置值恢复一致。当前侧栏切换器已重新加载。没有重启 Codex，没有发送模型推理请求，没有更改隐私设置。桌面原生菜单的显示、旧对话行为、实际请求路由和正常退出清理仍未验收，电脑操作工具不允许控制本次任务所在的 Codex App。

model_catalog_json 替换的是当前进程的目录，不是按每个旧对话的服务分别设置目录。Go 模式下旧 OpenAI 对话的可选列表也可能缩小；恢复 OpenAI 不会转换旧 Go 对话的来源。保存成功表示配置已保存，重启并新建聊天后才能验收生效。
